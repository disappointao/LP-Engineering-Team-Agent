# Real Builder Static Artifacts Design

Date: 2026-05-14

## Status

Approved direction: in real runtime mode, let the Builder model produce framework-free static LP artifacts as strict JSON, validate them before persistence, and fail closed on invalid or unsafe output.

This is the next Stage 3 slice after structured Planner `LPBriefSchema` output. The Planner can now create a validated `LPBrief`; this slice moves the next handoff from deterministic artifact generation toward model-generated static HTML/CSS/JS while preserving the current deterministic default path.

## Context

The project currently has:

- `packages/lp-schema` with `LPBriefSchema` and artifact-related schemas.
- `packages/model-gateway` with real `anthropic-messages` and `openai-completions` adapters.
- `packages/runtime-adapters` returning transient `modelOutputText`.
- `packages/api` parsing real Planner output into `LPBrief` when `REAL_MODEL_RUNTIME=1`.
- `packages/artifacts` with the canonical `StaticArtifacts` shape:
  - `indexHtml`;
  - `stylesCss`;
  - `scriptJs`.
- Web preview/download logic that derives a single-file HTML artifact from the canonical three-file static artifact.

The current gap is that the Builder still uses deterministic `generateStaticArtifacts(brief)` even when real model runtime is enabled. This keeps demos stable, but it means the real model can plan the LP brief while the final page code is still generated by a deterministic template.

## Goals

- In real runtime mode, make Builder output produce actual static artifacts.
- Keep the output contract framework-free and project-lightweight:
  - no React/Vue/Angular/Svelte application;
  - no Next/Nuxt/SvelteKit/Vite/Webpack build output;
  - no project scaffold;
  - no package installation;
  - no build step.
- Require Builder output to be strict JSON:
  - `indexHtml`;
  - `stylesCss`;
  - `scriptJs`.
- Validate model output before saving a `PageVersionRecord`.
- Preserve current deterministic behavior when `REAL_MODEL_RUNTIME` is not `1`.
- Preserve Web behavior: users can still download `index.html`, `styles.css`, `script.js`, and the derived single-file HTML.
- Fail closed on invalid, unsafe, or framework-dependent output.
- Keep raw provider text out of persisted run events, context packs, Web state, and snapshots.

## Non-Goals

- No repair retry in this slice.
- No streaming artifact generation.
- No visual/browser QA automation.
- No automatic deployment.
- No MCP/tool execution.
- No multi-file project scaffolding.
- No model-generated React/Vue/Angular/Svelte code.
- No model-generated package manifests, bundler configs, or install commands.
- No fallback to deterministic artifacts after a real Builder parse or validation failure.
- No fetching external CSS to inspect its contents.

## Activation

Real Builder artifact parsing should be active only when the system is already in real model mode:

```bash
REAL_MODEL_RUNTIME=1
```

Default behavior remains deterministic:

- `REAL_MODEL_RUNTIME` unset or not `1`: Builder keeps using `generateStaticArtifacts(brief)`.
- `REAL_MODEL_RUNTIME=1`: Builder prompt asks for strict artifact JSON, and API parses/validates the returned model text into `StaticArtifacts`.

This mirrors the structured Planner output slice and keeps ordinary tests, local demos, and development flows stable.

## Output Contract

V1 uses the existing canonical artifact contract:

```ts
interface StaticArtifacts {
  indexHtml: string;
  stylesCss: string;
  scriptJs: string;
}
```

The Builder model must return exactly one JSON object:

```json
{
  "indexHtml": "<!doctype html>...",
  "stylesCss": ":root { ... }",
  "scriptJs": "..."
}
```

The model must not wrap the JSON in Markdown fences or include prose before or after JSON. V1 should reject fenced or prose-wrapped output instead of trying to extract JSON from it.

## HTML Contract

`indexHtml` must be a complete static HTML document:

- includes `<!doctype html>` or equivalent document start;
- includes `<html>`, `<head>`, and `<body>`;
- includes a viewport meta tag;
- includes useful title/description metadata from the `LPBrief`;
- includes the existing local stylesheet marker:

```html
<link rel="stylesheet" href="styles.css">
```

- includes the existing local script marker:

```html
  <script src="script.js"></script>
```

Those markers preserve the existing `bundleSingleFileHtml()` path. Additional allowed external CSS links may appear beside the local stylesheet marker, but the local marker must remain present.

## External Resource Policy

The approved V1 policy is:

- Allow external images.
- Allow external font CSS.
- Allow non-framework brand/material CSS.
- Forbid external JavaScript.
- Forbid CSS framework CDNs and framework stylesheet dependencies.

Allowed examples:

- `<img src="https://...">`
- `<link rel="preconnect" href="https://fonts.googleapis.com">`
- `<link rel="stylesheet" href="https://fonts.googleapis.com/...">`
- a brand-owned CSS file that does not match known framework CDN/name patterns.

Forbidden examples:

- `<script src="https://..."></script>`
- `<script type="module" src="..."></script>`
- `javascript:` URLs.
- inline event handler attributes such as `onclick`, `onerror`, `onload`.
- Bootstrap, Tailwind CDN, Bulma, Foundation, Materialize, Ant Design CSS, or similar CSS frameworks.

V1 validation should be static string validation only. It should not fetch external resources.

## Framework-Free Policy

The artifact must not contain framework or build-output signals for:

- React;
- Next;
- Remix;
- Vue;
- Nuxt;
- Angular;
- Svelte;
- SvelteKit;
- Vite;
- Webpack;
- other obvious SPA/bundler runtimes.

Examples of forbidden markers:

- `__NEXT_DATA__`;
- `data-reactroot`;
- `ng-version`;
- `id="__nuxt"`;
- `id="svelte"`;
- `/@vite/client`;
- `webpackJsonp`;
- framework CDN URLs;
- package/build output references such as `/_next/`, `/assets/index-*.js`, or `node_modules`.

The validator should focus on framework and build markers in markup, script content, URLs, comments, and attributes. It should avoid rejecting ordinary marketing copy solely because it contains an incidental word such as "react" unless it is coupled with code/framework markers.

## Boundary Decision

Parsing and policy validation should live in `packages/api` for V1, similar to structured Planner output.

Reasoning:

- `packages/model-gateway` should stay provider/protocol focused.
- `packages/runtime-adapters` should stay role/runtime focused.
- `packages/artifacts` owns deterministic artifact generation and single-file bundling, but the real model parse/fail-closed behavior belongs to API orchestration.
- API already owns repository writes, run finalization, and user-visible failure behavior.

A small API-local parser module is appropriate, for example:

```ts
parseBuilderStaticArtifactsOutput(text: string): StaticArtifacts
```

The implementation can later move reusable artifact policy validators into `packages/artifacts` if other packages need the same checks.

## Builder Prompt Contract

When real Builder output is enabled, the Builder prompt should wrap the validated `LPBrief` with an explicit JSON artifact contract.

The prompt should require:

- output exactly one JSON object;
- no Markdown fences;
- no prose before or after JSON;
- fields `indexHtml`, `stylesCss`, `scriptJs`;
- complete static HTML;
- local `styles.css` and `script.js` markers;
- no framework, no build step, no package manager;
- no external JavaScript;
- no CSS frameworks;
- responsive LP layout based on the brief;
- clear CTA and product/offer sections when present in the brief.

The prompt can include a compact summary of the artifact policy instead of a long validator dump. The validator, not the prompt, is the source of truth.

## Parse And Validation Contract

V0 parser behavior:

- Trim returned model text.
- Reject empty output.
- Parse with `JSON.parse`.
- Reject non-object JSON.
- Validate `indexHtml`, `stylesCss`, and `scriptJs` as non-empty strings.
- Validate HTML structure and required local markers.
- Validate external resource policy.
- Validate framework-free policy.
- Return typed `StaticArtifacts` only after all checks pass.

V0 should not execute HTML, run JavaScript, fetch external resources, or rely on browser rendering.

## Run Flow

When `REAL_MODEL_RUNTIME=1`:

1. `DemoWorkbenchService.generatePageVersion()` loads the validated `LPBrief`.
2. API builds the structured Builder prompt from the brief.
3. `runAgentStep()` assembles Context Pack v0 and runs the Builder.
4. Runtime calls the configured real model provider.
5. Runtime returns sanitized `model.completed` metadata and transient `modelOutputText`.
6. API parses `modelOutputText` into `StaticArtifacts`.
7. On parse success:
   - replace deterministic runtime artifacts with parsed model artifacts;
   - persist `PageVersionRecord.artifacts` from parsed model output;
   - keep the Builder run completed;
   - persist sanitized parse success and artifact-created events.
8. On parse failure or policy violation:
   - do not save a `PageVersionRecord`;
   - mark the Builder run failed;
   - remove any misleading deterministic `artifact.created` / `run.completed` terminal events from the final persisted event list;
   - persist sanitized parse failure and `run.failed` events;
   - surface `Builder run failed.` to existing callers.

The runtime may continue to generate deterministic artifacts internally for default behavior. In real Builder mode, API finalization owns whether those artifacts are replaced or discarded before persistence.

## Sanitized Events

Parse success event:

```ts
{
  type: "model.output.parsed",
  message: "Builder output parsed as static artifacts",
  payload: {
    role: "builder",
    schema: "StaticArtifactsSchema",
    artifactKind: "three-file-static",
    htmlBytes: number,
    cssBytes: number,
    jsBytes: number,
    hasExternalCss: boolean,
    hasExternalImages: boolean
  }
}
```

Parse failure event:

```ts
{
  type: "model.output.parse_failed",
  message: "Builder output could not be parsed as static artifacts",
  payload: {
    role: "builder",
    schema: "StaticArtifactsSchema",
    reason: "empty_output" | "invalid_json" | "schema_invalid" | "policy_violation",
    policyCode?: string,
    issueCount?: number,
    firstIssuePath?: string,
    firstIssueCode?: string
  }
}
```

Do not include:

- raw model text;
- raw HTML/CSS/JS output;
- API key;
- env var name;
- full base URL;
- provider response body;
- request headers.

If existing `RuntimeEvent` type variants are too narrow for `StaticArtifactsSchema`, broaden them with explicit Planner and Builder variants rather than weakening event typing to arbitrary records.

## Error Handling

Stable failure categories:

- empty output -> `empty_output`;
- `JSON.parse` failure -> `invalid_json`;
- missing or non-string artifact fields -> `schema_invalid`;
- framework/external resource/security rule violation -> `policy_violation`.

Policy violations should include a sanitized `policyCode`, for example:

- `missing_stylesheet_marker`;
- `missing_script_marker`;
- `external_script_blocked`;
- `javascript_url_blocked`;
- `inline_event_handler_blocked`;
- `framework_marker_detected`;
- `css_framework_blocked`;
- `html_document_invalid`.

The user-facing error can remain broad in this slice:

```text
Builder run failed.
```

The timeline carries enough sanitized detail for debugging without exposing generated code or provider payloads.

## Testing

Add focused tests before implementation:

- Parser accepts a complete valid three-file static artifact JSON object.
- Parser rejects empty output.
- Parser rejects Markdown-fenced JSON in V0.
- Parser rejects invalid JSON.
- Parser rejects missing or empty artifact fields.
- Parser rejects missing `styles.css` or `script.js` local markers.
- Parser rejects external JavaScript.
- Parser rejects `javascript:` URLs.
- Parser rejects inline event handlers.
- Parser rejects common framework/build markers for React, Vue, Angular, Svelte, Next, Nuxt, Vite, and Webpack.
- Parser rejects CSS framework links.
- Parser allows external image URLs.
- Parser allows external font CSS or non-framework CSS links.
- Real-runtime API fake-fetch test persists model-generated artifacts instead of deterministic artifacts.
- Real-runtime parse/policy failure marks Builder run failed and saves no page version.
- Persisted events never contain raw generated HTML/CSS/JS.
- Default deterministic runtime still uses `generateStaticArtifacts()`.

Verification should include:

```bash
pnpm --filter @lp-agent/api test
pnpm --filter @lp-agent/runtime-adapters test
pnpm --filter @lp-agent/artifacts test
pnpm test
pnpm typecheck
pnpm build
git diff --check
```

The real provider integration tests remain opt-in and should stay skipped unless `REAL_MODEL_PROVIDER_TEST=1` is set.
